# v0.7 解析即总结 · 同屏工作台设计

> 版本：v0.7（2026-11-14）
> 状态：已实施，真实链路与浏览器验收通过
> 范围：前端布局重构 + 解析后自动触发 AI 总结；**不改动后端业务逻辑与任何现有接口契约**
> 关联文档：[需求分析](./requirements.md) · [实现总结](./implementation-summary.md) · [AI 总结设计](./ai-summary-design.md) · [v0.6 内容体验设计](./v0.6-content-experience-design.md) · [项目 README](../README.md)

> **v0.8 更新（2026-11-14）**：本文描述的「左栏吸顶」已由**两栏等高固定工作台**取代（固定 `100dvh - 5.5rem`，各自内部滚动）；「生成进度条」已由**思考态 + SSE 打字机**取代。v0.7 的其余结论（双栏、解析即总结、缓存不占额度）仍然有效。详见 [v0.8 总结流与等高工作台设计](./v0.8-streaming-summary-design.md)。

## 1. 结论

当前页面把「视频信息（播放器 + 清晰度 + 下载）」和「AI 总结」上下堆叠在一条 `max-w-3xl`（768px）窄列里，导致：

1. 桌面一屏内看不到总结，用户必须向下滚动上千像素；
2. 总结需要再点一次「生成总结」按钮，多一次操作；
3. 左栏内容过长（播放器 + 标题 + 三段说明 + 清晰度列表），即便并排也放不进一屏。

v0.7 的做法是**只重构前端结果区的信息架构**：

- 解析成功后进入**双栏工作台**：左栏 = 播放器 + 视频信息 + 清晰度 + 下载动作（吸顶）；右栏 = AI 总结（自动生成 + 标签页 + 长内容独立滚动）；
- **解析成功即自动生成总结**（可开关、命中缓存不计额度、不支持的视频降级为友好提示）；
- 左栏「清晰度列表」压缩为 **chips + 选中项详情 + 三个动作按钮**，把左栏高度压到 ~520px，保证 1440×900 下两栏同时可见；
- 移动端保持单列顺序（视频信息在上、总结在下）。

后端零改动，`/api/probe`、`/api/preview`、`/api/download`、`/api/summary*`、`/api/summary/{id}/ask` 的契约全部保持不变。风险集中在 `Home.vue` / `ResultPanel.vue` / `AiSummaryPanel.vue` 三个文件。

## 2. 现状核对（代码事实）

### 2.1 布局事实

| 位置 | 事实 |
|---|---|
| `Home.vue` | Hero 与结果区都用 `mx-auto max-w-3xl px-4 sm:px-6`；结果区内部按 `ResultPanel` → `TaskProgress` → `AiSummaryPanel` 顺序纵向排列，间距 `mt-8` / `mt-6` |
| `ResultPanel.vue` | 根节点 `mt-8 card overflow-hidden`；内部：16:9 播放器 → 标题（clamp-2）→ 平台/作者/字幕 chips → **一整段预览说明文字** → 清晰度列表（每行 展开按钮 + 「下载到本地」+ 直链/服务端转存）；高度随清晰度数量线性增长 |
| `AiSummaryPanel.vue` | 根节点 `scroll-mt-20 mt-6 card animate-float-in overflow-hidden`；头部渐变标题区 + 配置态 + 「生成总结」CTA + 进度卡 + 5 个标签页（总结/章节/文稿/思维导图/问答） |
| `TaskProgress.vue` | 独立卡片，`mt-6`，下载任务进度/速度/ETA/取消 |
| `PreviewPlayer.vue` | `aspect-video` 原生 video；`defineExpose({ seekTo })` |
| 全局 | `AppHeader` 为 `sticky top-0 z-40 h-16`；`style.css` 已有 `.md-body`（笔记排版）、`.card`、`.btn-primary` |
| 页面顺序 | Hero → 结果区 → Features → Steps → Pricing → FAQ |

### 2.2 交互事实

- `analyze()` 成功后：设置 `result`、默认选中第一个清晰度、**静默预取可直链清晰度的预览地址**（`preparePreview(true)`），但不自动总结。
- `AiSummaryPanel` 以 `:key="result.url"` 挂载，内部 `onMounted` 只拉 `/api/summary/config`，生成必须由用户点击。
- 时间戳跳转链路已通：`MarkdownNote`/章节/文稿 → `emitSeek` → `Home.summarySeek` → `ResultPanel.seekTo` → `PreviewPlayer.seekTo`。
- 卸载面板时会 `DELETE` 进行中的总结任务（`onBeforeUnmount`）。

### 2.3 额度与成本事实（决定自动总结策略）

- `SummaryTaskManager.create()`：**缓存命中直接返回 finished、不计额度**；否则 `_check_daily()` + `_increment_daily()`，默认 `VDS_SUMMARY_DAILY_LIMIT_PER_IP=3`。
- 单 IP 同时只允许 1 个总结任务（`summary_max_concurrent_per_ip=1`），超出返回 429“同时进行的 AI 总结任务已达上限”。
- 创建请求限流 `5 次/分钟`；`DELETE` 会立刻释放并发槽位。
- 无字幕视频走 ASR，按音频时长计费（刊例 0.78 元/小时）。

**推论：** 自动总结必须做成“默认开、可关闭、缓存优先、提前跳过不可能成功的视频”，否则会把每天 3 次额度在 3 次解析内烧完。

### 2.4 现有高度预算（1440px 宽、单列）

| 区块 | 估算高度 |
|---|---|
| Hero（badge + h1 + 副标题 + 搜索框 + 提示 + 平台 chips + 数据条 + 间距） | ≈ 560–620px |
| ResultPanel（播放器 225 + 标题/信息 90 + 说明段 70 + 4 行清晰度 ≈ 300 + 内边距 40） | ≈ 720px |
| AiSummaryPanel 头部 + CTA | ≈ 260px |
| 总结正文（笔记模式，3 章节 + 8 要点） | ≈ 1200px+ |

结论：一屏（900px 视口）内连「播放器 + 总结开头」都放不下，必须在结构上重排。

## 3. 目标与非目标

### 3.1 目标

| 编号 | 目标 | 可验证标准 |

| G1 | 桌面解析后，视频信息与 AI 总结同屏 | 1440×900 下滚动到工作台后，左栏（播放器/清晰度/下载）与右栏（总结状态或正文）在同一视口内可见，两栏 `top` 差 < 8px |

| G5 | 自动总结可控、可解释 | 有关闭开关并记忆；缓存命中不计额度；不支持/额度用尽/未配置时给出中性提示 + 手动入口 |

| G7 | 零回归 | 后端 95 个测试全过；`npm run build` / `tsc --noEmit` 通过；预览/下载/去水印/问答行为不变 |

- 不改后端接口、不加新接口、不改 `SummaryPayload` / 任务与缓存结构；
- 不做“多视频并列对比”“批量解析”；
- 不改思维导图导出、字幕下载、问答流式实现；
- 不引入前端路由、不引入状态管理库；
- 不改 Hero / Features / Pricing / FAQ 的内容与视觉。

## 4. 竞品参考与取舍

需求给出的参照（BibiGPT 总结页）核心特征是：**左侧固定视频卡 + 右侧内容区，右栏顶部用标签页切换 Summary / Chapter / Mind Map 等**。已经做过的调研（见 `v0.6-content-experience-design.md` 第 2 节）显示，主流产品都是“左视频、右内容”的双栏结构。

我们与竞品的差异点保持：**双栏里同时承载“下载”和“总结”**，而竞品一般只有总结没有下载。

取舍：

| 决策点 | 选择 | 理由 |
|---|---|---|
| 双栏还是“抽屉/弹层” | 双栏 | 需求要的就是同屏；弹层会遮挡播放器 |
| 左栏内容形态 | 紧凑卡（播放器 + chips + 动作） | 现有列表过长，无法一屏容纳 |
| 右栏滚动方式 | 页面滚动 + 左栏吸顶 | 避免双层滚动条；长笔记更自然 |
| 移动端 | 单列 | 375px 无法双栏；保持现有顺序 |
| 自动总结开关 | 默认开、可关、记忆 | 成本与体验平衡（见第 6 节） |

## 6. 自动总结方案

### 6.1 触发时机

```
用户粘贴链接 → analyze()
  ├─ 关闭旧总结任务（若存在，见 6.5 竞态）
  ├─ POST /api/probe → result 就绪
  ├─ 静默预取可直链清晰度的预览地址（现有逻辑，不变）
  ├─ nextTick → 平滑滚动到 #workspace
  └─ AiSummaryPanel 挂载 → loadConfig() → maybeAutoGenerate()
```

`maybeAutoGenerate()` 的前置校验（**全部在前端完成，避免无效请求**）：

| 条件 | 行为 |
|---|---|
| `config.enabled === false` | 不自动生成；右栏展示“AI 总结未启用（原因）”；布局降级单列 |
| 自动总结开关关闭 | 不自动生成；右栏展示现有「生成总结」CTA |
| `result.is_playlist` | 不请求；右栏提示“合集/播放列表暂不支持 AI 总结” |
| `result.duration > config.max_duration_seconds` | 不请求；右栏提示上限（复用现有文案风格） |
| 已取消过本视频的自动任务 | 不再自动重试，只留 CTA |
| 其余情况 | `POST /api/summary { url, force: false }` |

### 6.2 结果分支

| 返回 | 表现 |
|---|---|
| `202 cached=true` | 立即拉取任务，直接渲染总结（不计额度、无 ASR 费用） |
| `202 cached=false` | 进入现有进度态（阶段文案 / 百分比 / 已用时 / 取消） |
| `429`（今日额度 / 同 IP 并发） | 右栏中性提示 + 「立即生成」按钮；**不显示红色错误块** |
| `422`（时长/合集/时长未知） | 中性提示 + 原因；隐藏自动重试 |
| `503`（未配置 Key） | 复用现有“未启用”提示 |
| 网络错误 | 中性提示 + 重试按钮 |

### 6.3 开关

- 位置：右栏面板头部右侧，`解析后自动总结` 小开关（仅在 `config.enabled` 时显示）；
- 状态：`Home` 持有 `autoSummary` ref，`localStorage['vds-auto-summary']` 记忆（默认 `true`，读写 try/catch）；
- 组件间用 `v-model:auto-summary` 双向绑定；
- 关闭开关不会取消**已在进行**的任务（只影响下一次解析）；
- 手动点击「生成总结」不受开关影响。

### 6.4 额度与费用提示

- 面板头部保留“单视频 ≤ N 分钟 / 中文输出”徽章；
- 自动生成时，进度卡下方增加一行说明：`自动总结会占用每 IP 每日额度（默认 3 次/天）；命中缓存不占用额度。`
- 开发自测建议：把 `VDS_SUMMARY_DAILY_LIMIT_PER_IP` 临时调高，或复用已缓存视频（详见第 9 节）。

### 6.5 竞态与清理

| 场景 | 处理 |
|---|---|
| 连续解析两个视频 | `AiSummaryPanel` 以 `result.url` 为 key 会被卸载；新增 `@task-change` 让 `Home` 记住当前总结 `task_id`，`analyze()` 在 `probe` 之前 `await api.deleteSummary(id)`，确保并发槽位先释放，避免新视频自动总结偶发 429 |
| 卸载时的兜底 | 保留现有 `onBeforeUnmount` 的 `DELETE`（异步、不 await） |
| 用户取消自动任务 | 置 `autoCancelled = true`，不自动重启，显示 CTA |
| 自动生成中切换清晰度 | 面板不重挂载（key 未变），任务继续，互不影响 |
| `?url=` 分享链接自动解析 | 与手动解析同一路径，同样自动总结 |

## 7. 左栏（ResultPanel）改造细节

保持所有 props / emits / `defineExpose({ seekTo })` 不变，只重排模板。

| 区块 | 改造前 | 改造后 |
|---|---|---|
| 工具条 | 无 | 卡片顶部一行：`清晰度` 标题 + 去水印开关（chip 样式） |
| 清晰度 | 纵向列表，每行含展开按钮 + 主按钮 + 两个次级按钮 | **横向 chips**（`label` 文本 + 选中态），单行可滚动 |
| 选中详情 | 每行 `note · 约 xxMB` | 一行详情：`1080P · MP4 · 约 89MB · 支持直链`，`note` 单行截断 |
| 动作 | 每行都有三个按钮 | 选中项下方：主按钮「下载到本地」+ 次级「服务端转存 / 直链」（`直链` 仅在 `canDirect && !removeWatermark` 时出现） |
| 说明文字 | 常驻一大段（约 70px） | 折叠为 `<details>`「预览与下载说明」，默认收起 |
| 去水印 | 右侧 checkbox + 独立提示段 | 工具条内 chip 开关 + 选中时一行说明（条件渲染） |
| 标题/元信息 | 已紧凑 | 保持，压缩行距，元信息单行（平台 · 作者 · 时长 · 字幕数） |
| 空/异常 | — | 无清晰度时显示提示（现有行为） |

注意事项：

- `selectOption()` 的语义不变：切换清晰度会 `resetPreview()`，并对可直接播放的选项静默预取；
- 清晰度切换按钮需要 `role="radiogroup"` / `aria-checked`，chips 用 `<button type="button">`；
- chips 容器 `-mx-1 px-1 overflow-x-auto` + `scrollbar-hidden` 工具类（`style.css` 新增）；
- 保留 `id="result"`（E2E 脚本仍依赖）。

## 9. 失败模式与降级

| 场景 | 行为 |
|---|---|
| AI 未配置 / 总开关关闭 | 工作台降级为单列；右栏展示现有“未启用”提示（告诉用户如何配置） |
| `/api/summary/config` 请求失败 | `Home` 视作不可用 → 单列；面板自身显示现有“暂时不可用 + 重试” |
| 自动总结命中每日额度 | 中性提示“今日自动总结额度已用尽”+「重试」；不影响下载 |
| 自动总结触发同 IP 并发限制 | 见 6.5：先删除旧任务；仍 429 时提示稍后重试，不自动循环重试 |
| 视频超过 2 小时 / 合集 / 时长未知 | 前端直接拦截，不发请求；提示原因 |
| 自动总结失败（ASR/LLM 错误） | 保留现有红色错误卡 + 重试（这是真实失败，需要显性提示） |
| 左栏内容超过视口高度 | 左栏内部滚动（`lg:max-h-[calc(100dvh-5.5rem)] lg:overflow-y-auto`），播放器仍吸顶 |
| 极窄桌面（1024px）+ 长标题 | 左栏标题 `line-clamp-2`；右栏 `min-w-0`；chips 横向滚动 |
| 用户开启“减少动效” | 自动滚动改用 `behavior: 'auto'`（读 `prefers-reduced-motion`） |
| 总结任务过期 | 现有提示与「重新生成」按钮不变 |

## 13. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| 自动总结耗尽每日额度（默认 3 次/天） | 后续解析无法生成总结 | 默认开关可关闭；缓存命中不计额度；额度用尽给中性提示；文档建议自测期调高 `VDS_SUMMARY_DAILY_LIMIT_PER_IP` |
| 自动总结带来 ASR 费用 | 成本 | 缓存 6 小时；超时长前端拦截；进度卡说明计费规则 |
| 布局回归（移动端/平板） | 可用性 | 375/768/1024/1280/1440 五档截图核对 |
| sticky 在 `overflow-hidden` 祖先下失效 | 吸顶不生效 | `AiSummaryPanel` 根节点去掉 `overflow-hidden`，头部单独圆角；左栏容器不加 `overflow-hidden` |

| 自动滚动打断用户 | 体验 | 每次解析只滚动一次；尊重 `prefers-reduced-motion` |

### 14.4 实施中发现并修复的问题

1. **清晰度 chips 被裁切**：首版沿用横向滚动，416px 左栏只能显示 4 个半清晰度（“仅音频 MP3”完全不可见），与“全部信息可见”的目标冲突；改为 `flex-wrap` 两行展示，左栏仅增高约 33px（底边 664 → 697px），仍在 812px 可用高度内。
2. **次级动作可点击性弱**：首版「直链」「服务端转存」是灰色文本，视觉上像说明文字；改为 `.chip` 边框按钮，移动端自动换行居中。
3. **额度说明几乎不可见**：首版仅在 `starting && !task` 的极短窗口显示，实测截图里根本拍不到；改为整个生成过程中常驻。
4. **自动总结误判为“未启动”**：缓存命中时面板瞬间出结果，E2E 用「出现进度文案」判断会超时；改为「进度 / 笔记 / 手动 CTA」三者任一即视为已判定，并区分“未自动触发”的真实失败。
5. **sticky 依赖的祖先溢出**：`AiSummaryPanel` 原根节点 `overflow-hidden` 会让内部 `sticky` 失效；改为根节点不加 `overflow-hidden`、头部单独 `rounded-t-[1rem]`。
6. **AI 关闭时视频卡被“困”在吸顶滚动容器里**：左栏的 `lg:sticky` + `lg:max-h` + `lg:overflow-y-auto` 是无条件生效的，降级单列后视频卡被裁进 812px 的滚动框，`#ai-summary` 出现在卡片中间高度。修复为：吸顶/限高/内部滚动与容器宽度都跟随 `summaryAvailable` —— 双栏时 `max-w-[1400px]`，降级时回落到 `max-w-3xl` 并取消 sticky；降级验收通过（左栏底 777px、右栏顶 797px）。

### 14.5 遗留与限制

- 自动总结默认每次解析消耗 1 次额度（每天 3 次），自测期建议临时调高 `VDS_SUMMARY_DAILY_LIMIT_PER_IP` 或复用已缓存视频；
- 自动总结与在线预览并行执行，首次播放高清格式仍需要服务端合并，两者互不阻塞；
- 关闭开关只影响下一次解析，不取消正在进行的任务；
- 左栏内容超过视口时在栏内滚动（`lg:max-h-[calc(100dvh-5.5rem)]`），不新增页面级双滚动条；
- 笔记目录（TOC）内部滚动条仍为浏览器原生样式（v0.6 既有实现，本期未改）；
- 后端接口、任务与缓存结构完全未变，本次改动可用前端回滚单独撤销。
- **v0.8 变更（2026-11-14）**：左栏吸顶已改为两栏等高固定工作台；生成进度条已移除，改为思考态 + SSE 打字机。本文其余结论仍然有效，详见 [v0.8 总结流与等高工作台设计](./v0.8-streaming-summary-design.md)。
