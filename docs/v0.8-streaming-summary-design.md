## 1. 结论

本轮把「解析 → 等待总结 → 看结果」的体验从**进度条**改成了大模型式的**思考态 + 打字机输出**：

1. 总结未完成时不再出现百分比和进度条，只显示跳动圆点、「正在总结中…」、当前阶段文案和取消按钮；
2. 总结完成后**直接打开结果界面**（标签页、目录、笔记框架），再把已生成好的 Markdown 通过 SSE 逐块吐出，前端呈现打字机效果；
3. 桌面左右两栏改为**固定视口高度、彼此等高**的工作台，左栏不再随内容自然撑高；两栏各自内部滚动；
4. 顶栏「开通会员」改为图 4 的蓝色胶囊「升级 Pro」；
5. 本轮全部行为、契约、失败模式与验收记录沉淀到本文档。

后端只新增了**呈现层 SSE 端点**，没有改变总结生成、逐字稿、缓存、额度与任务模型；即使流式接口不可用，前端仍会回退到原有轮询，用户仍能看到完整结果。

### 2.2 为什么不是「真的 token 流式」

总结链路是：

```
逐字稿（平台字幕 / ASR）
  → 一次 DeepSeek Chat JSON 调用
  → 服务端校验、时间戳吸附、章节/要点归一化
  → build_markdown() 生成最终 Markdown
```

JSON 输出必须**完整**才能校验时间戳与结构，逐 token 流式会让前端拿到半截 JSON。v0.8 的取舍是：

- 生成阶段：后端不向模型开启 `stream`，仍然等完整总结；
- 呈现阶段：完成瞬间通过 SSE 发送 `meta`，随后把**已校验的 Markdown**按块 `delta` 下发；
- 前端：拿到块就追加，形成打字机；所有 tab 数据（章节、文稿、导图）在 `meta` 里已完整可用。

因此用户看到的「流式」是**呈现层流式**，不是模型 token 流；这与需求中「自定义 SSE 的数据封装发给前端，让前端解析」一致，也避免了破坏结构化总结。

## 3. 方案总览

```
用户粘贴链接
  └─ POST /api/probe
       └─ 解析成功 → AiSummaryPanel 自动 POST /api/summary
            └─ 202 {task_id, cached}
                 └─ GET /api/summary/{task_id}/stream   (SSE)
                      ├─ state*   未完成：status/stage/message → 思考态
                      └─ 完成：
                           meta   （完整 SummaryTaskStatus，含 summary）
                           delta* （{text}，48 字符 / 35ms 默认）
                           done   （终态）
```

- 结果界面在 `meta` 到达时打开；`delta` 只负责「把 Markdown 打出来」。
- 缓存命中时后端任务已 `finished`，SSE 会立即 `meta → delta → done`，不经过思考态。
- 生成失败发 `error`，任务被取消/删除发 `cancelled`/`gone`；前端分别进入错误卡或中性提示。

## 4. SSE 契约

### 4.1 端点

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/summary/{task_id}/stream` | 总结状态与内容流；`text/event-stream`；任务不存在在连接时返回 404 |

响应头：

```
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache, no-transform
X-Accel-Buffering: no
Connection: keep-alive
```

### 4.2 事件

| 事件 | 数据 | 说明 |
|---|---|---|
| `state` | `{status, stage, message}` | 未完成且状态变化时发送；**不包含 progress/百分比** |
| `meta` | 完整 `SummaryTaskStatus` | 任务完成、总结内容就绪；前端用它打开结果界面 |
| `delta` | `{text}` | `meta` 之后逐块下发；所有 `delta` 拼接后等于 `summary.markdown` |
| `done` | 完整 `SummaryTaskStatus` | 正常结束 |
| `error` | `{message}` | ASR / LLM / 未知错误 |
| `cancelled` | `{message}` | 任务被标记取消（DELETE 后通常表现为 `gone`） |
| `gone` | `{message}` | 任务不存在或已过期 |

SSE 帧示例（`services/qa/sse.py` 统一格式化）：

```
event: meta
data: {"task_id":"...","status":"finished",...,"summary":{...}}

event: delta
data: {"text":"## 一句话总结\n\n"}

event: done
data: {"task_id":"...","status":"finished",...}
```

### 4.3 分块、心跳与断开

- `iter_markdown_chunks(markdown, chunk_chars=48)`：优先按整行切分，超长行再按长度硬切；保证 `"".join(chunks) == markdown`。
- 默认每块 48 字符、间隔 35ms（`VDS_SUMMARY_STREAM_INTERVAL_MS`），约 1–2 秒打出 2–3KB 笔记。
- 未完成时每 0.8 秒轮询一次任务状态；状态无变化时每 12 秒发送一次 `: keep-alive` 注释行，前端忽略以 `:` 开头的块。
- 客户端断开（`request.is_disconnected()`）后立即停止读取，不会取消后台总结任务。
- Markdown 为空时只发 `meta → done`，不产生空 `delta`。

## 5. 前端状态机与打字机

### 5.1 阶段标记

`AiSummaryPanel` 在根节点暴露 `data-summary-phase`，作为 UI 与 E2E 的稳定状态：

| 阶段 | 触发 | 界面 |
|---|---|---|
| `idle` | 未创建任务 / 自动总结关闭 / 软失败 | 手动「生成总结」入口 |
| `starting` | 正在 `POST /api/summary` | 思考卡「正在创建总结任务」 |
| `thinking` | 已连上 SSE，任务未完成 | 思考卡「正在总结中…」+ 阶段文案 + 计时 + 取消 |
| `streaming` | 收到 `meta`，`delta` 进行中 | 结果界面 + 「正在输出」徽章 + 打字机 |
| `done` | 收到 `done` | 完整结果；复制/下载/切视图恢复 |
| `error` / `cancelled` | 对应终态 | 红色错误卡 / 中性提示 + 重试入口 |

### 5.2 状态流转

```
generate()
  ├─ POST /api/summary
  ├─ 失败 → error（自动触发时按可预期软失败处理）
  └─ attachStream(task_id)
       ├─ state → thinking（只更新文案，不显示进度）
       ├─ meta  → streaming（task 就绪，stopElapsed，打开结果界面）
       ├─ delta → streamText += text（MarkdownNote 增量渲染）
       ├─ done  → task=final，finishStream，切到总结页并拉取文稿
       └─ error/cancelled/gone → 对应终态
```

兜底：

| 场景 | 处理 |
|---|---|
| SSE 请求失败（404/网络/代理拦截） | 自动回退 `GET /api/summary/{id}` 轮询，不一直停在思考态 |
| SSE 正常 EOF 但没有终态事件 | 同上回退轮询，避免停在「正在输出」 |
| 用户取消 / 切换视频 / 卸载 | abort SSE + `DELETE` 任务；不变更额度逻辑 |
| 缓存命中 | 立即 `meta`，直接进入结果界面并打字；不显示思考态 |
| Markdown 为空 | 自动回退卡片视图，正文打不出来时仍能看到 TL;DR/要点 |

### 5.3 打字机期间的交互限制

- 标签页（总结/章节/文稿/思维导图/问答）在 `meta` 后即可点击，章节、文稿、导图数据是完整的；
- 「笔记 / 卡片」分段控件保持可见但**禁用并降低透明度**，避免中途切换打断打字效果；
- 复制 Markdown、下载 `.md`、重新生成在打字期间隐藏，结束后恢复；
- 笔记时间戳在打字期间不可 seek（`seekable && !streaming`），结束后恢复；
- 思考卡与「正在输出」徽章带 `role="status" aria-live="polite"`；不逐字播报正文，避免读屏噪音；
- 首块到达前显示轻量占位（三点 + 骨架），不会闪「没有 Markdown 笔记」。

## 6. 等高固定工作台

### 6.1 结构

```
#workspace  mx-auto max-w-[1400px]  （AI 未启用时降级 max-w-3xl）
└─ .grid  lg:h-[calc(100dvh-5.5rem)]  lg:grid-cols-[minmax(340px,420px)_minmax(0,1fr)]
   ├─ 左栏  lg:flex lg:h-full lg:min-h-0 lg:flex-col lg:overflow-y-auto
   │   ├─ ResultPanel（lg:h-full lg:flex-1；播放器/信息固定，下方控件区内部滚动）
   │   └─ TaskProgress（按需，出现时左栏内部滚动）
   └─ AiSummaryPanel（lg:h-full lg:min-h-0 lg:flex-col lg:overflow-hidden）
       ├─ 头部（固定）
       └─ 正文（lg:flex-1 lg:overflow-y-auto）
```

- 高度：`100dvh - 5.5rem`（5.5rem = 64px 顶栏 + 24px 间距）；带 `100vh` 降级（`supports-[height:100dvh]`）。
- 1440×900：两栏 `top=80`、`height=812`，底部 892px，落在视口内。
- 1280×800：两栏 `top=80`、`height=712`。
- 1024–1279px：仍双栏，左栏 340px；<1024px：单列、自然高度，顺序为视频信息 → 总结。
- 旧 v0.7 的「左栏 sticky」已移除：页面滚动时整个工作台一起移动；长内容在栏内滚动。
- AI 未启用：不套用固定高度，回落 `max-w-3xl` 单列，避免把视频卡困在空高度容器里。

### 6.2 视觉收口

- 左栏「预览与下载说明」使用 `lg:mt-auto` 贴到卡片底部，内容较少时不至于留下无意义的空白；
- 右栏标签栏 `lg:sticky lg:top-0` 在正文滚动时保持可见；
- 两栏内容限宽：左栏控件自然宽度，右栏笔记/卡片 `max-w-[52rem]`。

## 9. 失败模式与降级

| 场景 | 行为 |
|---|---|
| 缓存命中 | 不经过思考态，直接结果界面 + 打字机；不占额度 |
| SSE 404 / 网络失败 | 前端回退轮询，思考态继续，最终展示完整结果 |
| 代理提前关闭 / 无终态 EOF | 前端回退轮询；已收到的 `streamText` 最终由完整 Markdown 替换 |
| 生成失败（ASR/LLM） | `error` → 红色错误卡 + 重试；无进度条 |
| B 站 PCDN 节点拒绝连接（`WinError 10061`） | 音频下载失败后自动重新解析并降码率（`worstaudio/best`）重试一次；仍失败才返回「音频下载失败」。属于 B 站 PCDN 偶发节点问题，可稍后重试或换视频 |
| 任务过期 / 被删除 | `gone` → 中性提示 + 生成总结入口 |
| 用户取消 | abort SSE + DELETE，回到初始入口，不自动重启 |
| 切视频 / 卸载 | 组件卸载时 abort + DELETE，释放单 IP 并发槽位 |
| Markdown 为空 | 自动回退卡片视图，仍能看到 TL;DR/要点 |
| 超长 Markdown | 打字时长随分块线性增长；可用 `VDS_SUMMARY_STREAM_INTERVAL_MS` 调快/关闭 |
| 打字期间点时间戳 | 禁用 seek；结束后恢复 |
| AI 未启用 | 单列降级布局，无自动开关，显示未启用原因 |
| 移动端 / 低高度 | <1024px 单列；桌面两栏内部滚动，不出现页面横向滚动 |
| 旧浏览器不支持 `dvh` | 使用 `100vh` 降级 |

### 11.2 实施中确认的细节

1. **缓存命中与思考态**：缓存任务已 `finished`，SSE 立即 `meta`，不会出现思考动画；这符合「命中缓存秒出」的预算。E2E 为覆盖思考路径，检测到 initial streaming/done 后自动点「重新生成」。
2. **思考计时**：`meta` 到达即 `stopElapsed()`，计时只属于等待阶段；结果页显示的是后端统计的 `elapsed_seconds`。
3. **首帧空态**：`meta` 与首个 `delta` 可能分帧到达；增加「正在整理总结内容…」占位，避免闪出「没有 Markdown 笔记」。
4. **流没有终态事件**：代理可能在 EOF 时截断；`attachStream` 检测到「流结束但仍是 streaming」时回退轮询，避免永久「正在输出」。
5. **吸顶已移除**：v0.7 的 `lg:sticky` 与 E2E 吸顶断言不再适用；改为验证「页面滚动时两栏一起移动」。
6. **移动端不能被固定高度污染**：固定高度只作用于 `lg`，375px 下工作台高度为自然内容高度。
7. **B 站 PCDN 偶发 10061（补充修复）**：用户视频 `BV11XWR6ZEBu` 的音轨全部指向 `mcdn.bilivideo.cn:8082`，节点偶发拒绝连接；已在 `source.download_audio` 增加「重新解析 + `worstaudio/best` 降码率」二次尝试，并用该视频实测音频下载成功（4.39MB）。

### 11.3 已知限制

- 打字机是**呈现层流式**，模型实际仍是完整 JSON 一次返回；因此等待时间 = 生成时间，之后才开始打字。
- 打字时长随 Markdown 长度线性增加；超长总结可通过 `VDS_SUMMARY_STREAM_INTERVAL_MS` 调快或设 0 关闭。
- SSE 需要反向代理关闭缓冲（响应已带 `X-Accel-Buffering: no`）；个别网关仍可能缓冲，此时前端会回退轮询。
- 浏览器验收在 Chrome 上完成；Safari/Firefox 的 SSE 与 `dvh` 兼容性未单独验证。
- 真实 DeepSeek 链路本轮未重复消耗额度；v0.7 已验证真实 ASR/总结，本轮以 Mock 验证 UI/流契约与回归。

## 12. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| 代理缓冲 SSE | 打字机变成一次性出现 | `X-Accel-Buffering: no` + 前端轮询回退；文档记录 |
| 长总结打字过久 | 用户等待 | `summary_stream_interval_ms` 可调；默认 35ms/48 字符；必要时设 0 |
| 固定高度在低分辨率下过矮 | 控件需要内滚 | 左/右栏内部滚动；1024×768 仍可用；<1024px 单列 |
| 缓存命中跳过思考态被误判为「没生效」 | 验收误报 | E2E 明确区分 `initial-phase`，缓存命中时强制重新生成 |
| 旧 E2E 断言过时 | 回归误报 | 本轮同步更新 workspace/content/degraded 脚本 |
| 文档与行为漂移 | 误导 | 本文记录实测数字；requirements / README / implementation-summary 同步版本 |

回滚：

- SSE 端点是附加能力，回滚前端即可恢复轮询；后端端点可保留。
- 布局/Pro/思考态集中在 `Home.vue`、`ResultPanel.vue`、`AiSummaryPanel.vue`、`AppHeader.vue`、`style.css`；恢复这些文件并重建 `frontend/dist` 即可。
