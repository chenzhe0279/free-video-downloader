## 1. 背景与问题

用户有把网络视频保存到本地的强烈需求，但现状存在三类摩擦：

1. **平台不提供下载能力** —— 部分站点完全没有导出入口。
2. **下载体验差** —— 清晰度被限制、需要安装插件/客户端、不支持批量。
3. **跨端不一致** —— 手机上尤其难操作，通常只能依赖第三方 App 且广告多。

因此需要一个**网页端、免安装、跨设备**的视频下载工具：粘贴链接即可解析并保存。

在下载能力之外，用户还遇到两类学习/理解问题：

4. **长视频学习成本高** —— 1 小时课程需要完整看完才能知道重点，缺少快速大纲、要点和定位手段。
5. **看完了但记不住/找不到** —— 需要针对视频内容追问，而不是重新拖进度条；同时不希望 AI 对无关问题胡编。

## 2. 项目目标

| 维度 | 目标 |
|------|------|
| 能力 | 覆盖主流 + 长尾站点（借助 yt-dlp 的解析能力） |
| 体验 | 粘贴 → 选清晰度 → 保存，全程 3 步，无注册即可用 |
| 学习 | 解析后可直接在线预览、AI 总结、按时间戳回看、针对总结提问 |
| 性能 | 解析结果秒级返回，下载有实时进度；AI 问答逐 token 流式呈现 |
| 跨端 | 桌面与手机同一套界面，自适应布局 |
| 商业 | 首页具备付费转化引导（会员权益区），为后续变现留位置 |
| 成本 | 先不引入数据库；服务端存储按 TTL 自动清理；AI 调用有额度与缓存 |
| 安全 | API Key 只在服务端；AI 问答严格基于视频总结，无关问题拒答 |

## 3. 用户画像与场景

- **内容研究者 / 学生**：需要把公开课、讲座存档，追求高清晰度与字幕；也需要 AI 大纲、要点和追问。
- **运营与创作者**：需要参考素材，追求批量与速度。
- **普通用户**：手机上一键保存喜欢的短视频，追求“能用、不折腾”。

典型场景：

1. 用户在 B 站看到想收藏的视频 → 复制链接 → 粘贴到本站 → 选 1080P → 保存。
2. 用户想下载 YouTube 视频的高码率版本 → 直链下载被防盗链拒绝 → 切换“代理加速”。
3. 用户手机浏览器打开本站 → 全宽搜索框 → 下载完成后直接存入相册/文件。
4. 学生打开一个 1 小时讲座 → 生成 AI 总结 → 先看 TL;DR 和章节 → 点击时间戳回看具体片段 → 导出 Markdown 笔记。
5. 学生对总结中的某一点追问 “再展开说说第一点” → AI 基于总结回答；问 “今天天气怎么样” → 被明确拒答。
6. 用户想快速理解视频结构 → 切到「思维导图」→ 缩放/拖拽查看彩色分支，点击圆点折叠不关心的部分。

## 4. 功能需求

### 4.1 下载与预览（MVP，已完成）

| 编号 | 需求 | 说明 |
|------|------|------|
| F1 | 链接解析 | 输入视频页面 URL，返回标题、封面、时长、作者、平台、可用清晰度列表 |
| F2 | 清晰度选择 | 展示真实可用格式（含 ext、预估大小、是否支持直链） |
| F3 | 服务端转存下载 | 后端下载并合并音视频，前端轮询进度，完成后提供下载链接 |
| F4 | 直链下载 | 解析出平台直链后由浏览器直接下载，不占服务器带宽 |
| F5 | 代理下载 | 后端流式转发直链，注入 Referer/UA，支持 Range |
| F6 | 进度反馈 | 下载进度、已下载大小、总大小、剩余时间 |
| F7 | 过期清理 | 服务端文件保留 1 小时后自动删除 |
| F8 | 限流与安全 | 单 IP 解析/下载频率限制、并发上限、SSRF 防护、大小上限 2GB |
| F9 | 付费引导 | 首页会员权益展示区（本期不接入真实支付） |

v0.3 补充：

| 编号 | 需求 | 说明 |
|------|------|------|
| F10 | 在线预览 | `POST /api/preview`；单文件边下边播，分离格式服务端合并后播放，支持 Range |
| F11 | 下载到本地 | 服务端合并后流式传回浏览器；临时副本按 TTL 清理 |
| F12 | 抖音无水印 | 专用解析，不需要用户 Cookie；`playwm` → `play` |
| F13 | 按视频去水印 | 对配置表中登记的视频执行 ffmpeg `delogo`，有损重编码 |

### 4.2 AI 视频总结（v0.4，已完成）

| 编号 | 需求 | 说明 |
|------|------|------|
| F14 | 逐字稿获取 | 平台字幕优先（VTT/SRT/ASS/Bilibili JSON/YouTube json3）；无字幕时下载音频，按 60 秒分片调用 DeepSeek ASR |
| F15 | 结构化总结 | `deepseek-flash` 输出 TL;DR、概述、关键词、章节、核心要点、概念、思维导图，服务端校验并生成 Markdown |
| F16 | 时间戳定位 | 字幕使用原始时间戳；ASR 使用 60 秒分片起点；服务端把模型输出吸附到真实时间标记，避免编造中间时间 |
| F17 | 结果展示与导出 | 总结 / 章节 / 文稿 / 思维导图标签页（问答见 4.3）；复制 Markdown、下载 `.md` |
| F18 | 额度与缓存 | 默认单视频 ≤2 小时、每 IP 每天 3 次；缓存 6 小时；任务与缓存内存态，重启丢失 |

### 4.3 视频内 AI 问答（v0.5，已完成）

| 编号 | 需求 | 说明 |
|------|------|------|
| F19 | 严格基于总结 | 问答上下文只使用当前视频的 AI 总结，不加入逐字稿；总结覆盖不到的内容回复“材料中没有提到” |
| F20 | 相关性 gate | 先判断问题是否关于当前视频；天气、写代码、闲聊、问模型自身等无关问题固定拒答 |
| F21 | SSE 流式回答 | `POST /api/summary/{task_id}/ask` 返回 `text/event-stream`；事件为 `status` / `token` / `refusal` / `done` / `error` |
| F22 | 多轮对话 | 保留最近 3 轮（6 条消息）；gate 参考最近 1 轮，回答参考最近 3 轮 |
| F23 | 交互控制 | 前端支持停止生成、推荐问题、过期提示重新生成；切换标签不丢失会话和进行中的流 |
| F24 | 额度与成本 | 默认每 IP 每天 30 问、每分钟 10 次；提问延长总结任务 TTL |

## 5. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 解析请求 P95 < 8s（受平台响应影响）；下载支持并发分片；AI 问答首 token 目标 < 10s，逐 token 输出 |
| 可用性 | 单任务失败不影响其他任务；进程重启后任务丢失可接受（本期无数据库）；AI 无 Key 时下载/预览不受影响 |
| 安全 | 拒绝内网/环回地址访问；限制单 IP 并发与频率；文件大小上限；DeepSeek Key 只在服务端 |
| AI 安全 | 严格基于总结回答；无关问题拒答；不把逐字稿/视频/音频发给问答模型；系统提示防注入 |
| 成本 | ASR 按音频时长计费；总结缓存复用；默认 2 小时/3 次/天；问答 30 次/天；所有额度可配 |
| 合规 | 明确版权声明；不保存用户账号 Cookie；不代用户登录平台 |
| 可维护 | 下载能力委托 yt-dlp；AI 能力封装在 `services/summary` 与 `services/qa`；升级只需更新依赖 |
| 可移植 | 前后端分离，前端纯静态产物，后端单进程可跑；支持 Docker 部署 |
| 可观测 | 任务/问答日志只记录任务 ID、长度、耗时、token 用量，不记录完整问题/回答/Key |

## 6. 约束与风险

1. **版权与合规风险**：工具本身中立，但使用者可能下载无授权内容。需在页脚、README 显著声明。
2. **平台风控风险**：公网大规模使用可能导致服务器 IP 被平台限流甚至封禁。缓解：限流、默认不并发批量、建议加邀请码。
3. **直链时效性**：平台直链通常数小时失效，不能长期缓存。
4. **格式限制**：HLS/DASH 分离音视频格式无法直链，必须走服务端合并（依赖 ffmpeg）。
5. **无数据库**：任务状态、AI 缓存、问答额度在内存中，重启即丢；问答历史只存在前端页面内存；多进程部署需改造为共享存储。
6. **AI 依赖风险**：DeepSeek API 不可用、余额不足、限流或网络超时会直接影响总结/问答；无 Key 时功能降级。
7. **ASR 限制**：单次最长 120 秒、最大 8 MiB；本实现按 60 秒分片，ASR 时间戳只有约 1 分钟粒度。
8. **AI 准确性**：总结和问答可能遗漏或误判；通过时间戳吸附、严格 grounding、拒答和 UI 免责声明降低风险，但不承诺 100% 准确。
9. **问答 gate 误判**：相关性判断可能把边缘问题误判为无关或反之；通过 prompt 示例、真实样本调优和 fail-closed 处理。
10. **SSE 透传**：后端直连已验证流式；生产反代/Vite 代理需关闭缓冲，响应已带 `X-Accel-Buffering: no`，浏览器使用 `fetch` 流式读取。

## 7. 验收标准

### 7.1 下载与预览（历史 MVP）

1. 粘贴一个真实 YouTube/Bilibili 链接，能正确展示封面、标题与至少 2 个清晰度选项。
2. 选择“服务端转存”，进度条实时推进，结束后“保存到本地”可获得可播放文件。
3. 选择一个支持直链的格式，“直链下载”能启动浏览器下载；“代理加速”能在直链 403 的情况下成功下载。
4. 手机浏览器（375px 宽度）下页面布局正常，操作可达。
5. `/docs` 可访问 OpenAPI 文档；`/api/health` 返回服务状态。
6. 超时 1 小时后，服务端文件被自动清理。

### 7.2 AI 视频总结（v0.4）

1. 无平台字幕的 B站/抖音视频可完成 ASR → 总结；有字幕时优先字幕。
2. 总结包含 TL;DR、≥3 章节、≥5 要点、文稿、思维导图，时间戳均在视频时长内。
3. 章节/文稿时间戳可跳转在线预览；Markdown 可复制/下载。
4. 第二次请求同一视频命中缓存；`force` 可重新生成。
5. 超过 2 小时、合集、直播、无对白视频返回明确提示。
6. 62 个后端测试中覆盖总结任务、字幕、ASR、时间戳、缓存/额度/错误映射。

### 7.3 AI 视频问答（v0.5）

1. 总结完成后出现「问答」标签；相关问题通过 SSE 逐 token 显示，首 token <10 秒。
2. 无关问题（天气/写代码/闲聊/问模型自身）返回固定拒答和推荐问题，不产生答案正文。
3. 与视频相关但总结没覆盖的问题回复“材料中没有提到”，不补充外部知识。
4. 多轮追问（最近 3 轮）可理解指代；切换标签不丢失会话。
5. 停止按钮生效并保留已生成内容；任务过期提示重新生成。
6. 429/503/404/409/422 返回明确文案；现有总结/预览/下载不受影响。

### 7.4 Markmap 思维导图（v0.5）

1. 渲染出彩色分支、分支同色文字和根节点胶囊。
2. 支持滚轮缩放、拖拽移动、点击圆点展开/收起。
3. 桌面与 375px 移动端可正常浏览；控制台无异常。

## 8. 术语表

| 术语 | 含义 |
|------|------|
| 直链 | 平台 CDN 上可直接下载的媒体文件地址（通常带签名与时效） |
| 服务端转存 | 后端先下载文件到服务器磁盘，再提供给用户下载 |
| progressive 格式 | 音视频封装在同一文件中的格式（可直接直链下载） |
| DASH/HLS | 音视频分离的流式协议，需下载后合并 |
| yt-dlp | 开源视频下载引擎，本项目以其为唯一下载能力来源 |
| 逐字稿 | 视频完整口播文本；AI 总结的输入 |
| ASR | 自动语音识别，把音频转成文字；本项目使用 DeepSeek ASR |
| TL;DR | 一句话总结，帮助用户快速判断视频是否值得继续看 |
| 相关性 gate | 问答前判断问题是否关于当前视频的轻量模型调用 |
| 拒答 | 对无关问题返回固定提示，不调用回答生成模型 |
| SSE | Server-Sent Events，服务端逐事件向浏览器推送 token/状态 |
| Markmap | 将层级数据渲染为交互式思维导图的前端库 |
